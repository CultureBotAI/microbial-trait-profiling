# Verified additive multiplicity sidecars

Issue #853 adds a post-arm stage. It reads one completed, verified ComparisonRun,
its core bundle and all three ArmRuns. It does not modify native tables, call
flags, plots, arm plans, or the publication record.

```bash
just rerun-multiplicity /path/to/comparison_run.json /path/to/new-sidecars
just rerun-verify-multiplicity /path/to/new-sidecars
```

The output directory must be new and disjoint from all source bundles. This is
an additive diagnostic command, not part of an owner arm rerun. Running it does
not authorize a publication change or establish validity of the native p-values.

The stage requires AnalysisBasis records whose catalog hash, retained feature
count, ordered profile-header filter identity, profile unit and strain scope
match the verified core. Independent membership checks use catalog feature sets
and hash the ordered profile columns. The complete consumed AnalysisBasis must
also equal the current core-derived producer contract, including its catalog
ordering, aggregation, denominator, background and weighting declarations.
This establishes consistency with that producer; the scientific-label caveat
tracked in #817 remains upstream and is not silently relabeled by the adapter.
The filter identity is the hash of the ordered retained features, not the catalog
file hash. Historical ComparisonRuns affected by #860 must be regenerated by the
corrected producer; the adapter rejects them. Fresh comparisons also require
the recorded-arm-path fix in #829; phenotype-scope comparisons require the
corrected scope producer in #828. No 317- or 344-feature assumption
is embedded in the adapter.

| Family | Independently declared inventory | Imported primary p |
|---|---|---|
| Noel full screen | Every retained non-MediaDive qualified feature | `binomial_p` |
| Jed ratios | All 15 ordered numerator/reference pairs, with resolved qualified feature groups and study eligibility identities | `sign_p` |
| Native pooled composition | Core paired human profiles; support at least 6 and at most `max(2, floor(.95*n))`, nonzero fraction variance, no trait-count cap | `study_p_value` |
| Ilyas joint ORA | Paired profiles with N>0, retained features with background K>0, both upper and lower tails | `p_value` |

The native transformed-composition filter is reconstructed from core inputs,
not inferred from selected result rows. Its retained vocabulary size is separate
from its filtered test-family size. Historical native zero-total inclusion is
preserved. Nondefault filters, external unbound native statistics, unsupported
method versions, missing tail exports, truncated families and duplicate members
are rejected rather than filled in from selected tables.

Noel exports p-values to six significant digits. Corrections use those exported
values unchanged, so tiny differences from its native q-values may reflect
rounding. Missing tests require an explicit recognized untestable status, checked
against exported study sign tallies or native study support and dispersion.
Screen tallies and ratio eligibility ledgers must reconcile to the independently
loaded core cohort. Undefined native q-values must follow their producer's
convention: null for Noel/Jed and internal p=1 correction for native composition.
Untestable members count conservatively as p=1 and export null p, q and rejection
flags. Invalid numeric values, negative zero and status/p mismatches fail.
Effects and native row contents are bound
by source hashes and row hashes, and are never rewritten.
Cross-product reconciliation beyond these checks is tracked in #976: independently
reconciling every untestable status against source study effects, verifying native
ORA q-values against each complete tail, and versioning the free-text reason
vocabulary. Standalone adapters with upstream verification bypassed do not provide
that stronger scientific contract. Publishing always requires the recorded-byte
binding described below.
The shared canonical serializer uses strict JSON for these identities: numeric
NaN and infinity are rejected even inside nested basis or membership records.

Version 1.1 records typed hypothesis coordinates. ORA identifies the exact
study/experiment/direction profile; pooled screen, ratio and composition tests
use empty coordinates. Scientific duplicates are rejected independently of row
aliases or eligibility hashes. Each family carries its verified strain scope
and ordered retained-feature filter identity.

Each family produces separate `declared.jsonl`, `raw.jsonl`, `adjusted.jsonl` and
`migration.tsv` artifacts. SQLite checks membership and joins native rows on
disk. SciPy corrects one complete family using numeric arrays: ORA is never
split into arbitrary batches or rescaled from already adjusted q-values.
Correction memory therefore scales with numeric vectors, rather than millions
of Python hypothesis objects. Disk space scales with the full declared inventory.
Issue #871 requires a measured memory/runtime check on a real complete ORA family
before final production use; synthetic fixtures do not establish that measurement.

`multiplicity_run.json` conforms to the separate LinkML multiple-testing schema.
It records policy, input and output identities, code, NumPy/SciPy versions, timestamp,
population, direction, strain scope, and family summaries. Family source IDs are
content-addressed product names, not machine-specific paths. The explicit local
ComparisonRun path permits verification against the original execution records.
The code identity covers every Git-tracked Python module under canonical `src/mtp`, keyed
by its relative path, so shared loaders, scientific helpers and serializers are
included without filename collisions. Untracked scratch files and editor lock
symlinks are excluded. Changes to a tracked canonical module require
a new sidecar execution. Unresolved canonical Python entries in the Git index
are rejected until the merge conflict is resolved (#977).
The inventory prefix is derived from the actual package location inside its
repository; it must include the executing `stage.py`. An unrelated outer
repository or an incomplete copied package cannot produce an empty fingerprint.
Implementation and policy identities are captured before
source verification and family construction, then rechecked before the final
manifest is published. A change during execution refuses publication; the manifest
cannot claim a new disk implementation after detecting changed tracked bytes.
This contract starts at run entry; it does not attest bytecode imported before
entry. Fresh CLI execution is the supported reproducible invocation.

Source identities come from the verified parent inventories. Each native result
or support TSV pass read through the adapters hashes its exact raw bytes,
including comments and line endings, before CSV decoding; exhausting the pass
must match the recorded upstream hash.
This catches a changed export even if it is restored after correction and
migration. Other consumed inputs, including core profiles and experiments, are
checked at metadata and final-source boundaries against those recorded identities.
A rejected run has no final `multiplicity_run.json`;
partial diagnostic files may remain. These checks cover the recorded inputs and
consumed export streams, not arbitrary filesystem mutation or pre-entry imports.
In particular, a transient edit to a core table, label table or JSON input can
escape boundary checks when restored before them; closing that consumed-byte
gap is tracked in #983. The shared recorded-arm-output resolver consolidation is
tracked in #984. Neither deferred item is implied complete by these guards.

`migration.json` and the per-family migration tables distinguish three changes:

1. ORA membership changes from two native tail families to one joint family.
   Compare native BH with joint BH at a common threshold.
2. Compare BH and BY within the same complete family at q <= 0.05.
3. Compare BY q <= 0.05 with BY q <= 0.001 without changing family or method.

Native ORA hit flags also use fold cutoffs; these are separate from multiplicity
rejection. The native bounds are inclusive: enrichment accepts fold 1.5 and
depletion accepts fold 0.5 when the native q threshold also passes.
No full-screen q-value is attached to focal rows by trait slug. The
historical focal selection and the native support/variance filter remain
selection limitations. The sidecars make no global FDR claim across different
arms/families and do not measure physiological activity.

Verification checks the exact output inventory and reconstructs every family,
raw table, corrected result, migration report and manifest from verified native
sources. Altered q-values, policy, source bindings, scientific metadata or code
fail even if an output file checksum was updated. The verifier requires the
implementation and NumPy/SciPy versions used to produce the sidecars.

Tests include independent arithmetic expectations, full and oriented-subset
synthetic exports, changing feature counts and strain scopes, tested and undefined
ratios, missing/duplicate members, tampering and row-order independence. Separate
producer integration invokes the actual ORA exporter for both complete tails,
including its background identity headers. Separate
integration tests execute actual off/phenotype/full core fixtures and bind the
committed AnalysisBasis producer's outputs to verified count/ORA bundles; full
scope is rejected. The four-arm adapter fixture stubs the upstream comparison
execution-verification boundary, which the existing workflow tests cover.
Its native pooled statistics come from the actual infographic producer's
selection, transformations and statistical functions, independently of the adapter.

## Updating the author branch after a base merge

Merge `origin/main` into this branch; **never rebase it**. Important implementation
and regression changes live inside merge commits, including `c492273` and
`d8845cb`. A rebase can drop those changes together with their tests while leaving
a superficially passing suite (#979). Resolve the known foundation conflicts by
retaining both the accepted base and the sidecar fixes.

Before publishing the updated author branch, require the retained fix commit
and explicitly named regression/probe files, then run the complete focused and
required gates:

```bash
git merge origin/main
git merge-base --is-ancestor d8845cb HEAD
git ls-files --error-unmatch src/mtp/multiplicity/sources.py \
  tests/test_multiplicity_regression_guards.py \
  scripts/adhoc/issue979_probe_multiplicity_boundaries.py
just test-multiplicity-adapters
just precommit
just check
just core-fixture
```

The ancestry check applies to this author branch before its PR is merged, not to
the owner's eventual squash commit on main. The explicit file checks ensure a
missing test file is a failure rather than a smaller silently passing test suite.
